# PARKLY — mobile build plan (Next.js)

Source of truth: `prototype/src/mobile.html` (screens + native layer), `prototype/src/engine.js`, `prototype/src/core.css`; built reference `prototype/out/PARKLY_Mobile_v1.0.html` (open it in Playwright at 390×844 to compare looks/motion). Already ported: `styles/mobile.css` (all mobile CSS, scoped `body.m`, keyframes `mk-*`), `lib/*` (data, engine, actions, store, device), `components/shared/*`. The desktop port in `components/desktop/*` is the reference for how prototype string-HTML became React (hooks, `useApp()`, `useNow()`, `Sheet`, `useToast`, `useConfirm`). Do NOT redesign: match the prototype pixel-for-pixel and motion-for-motion. Read `docs/NEXT_PLAN.md` (hard requirements) and `docs/CORE_API.md` (engine names) first.

## Architecture (phase 1 — shell + kit, one builder)

Files owned: `components/mobile/MobileShell.tsx`, `components/mobile/kit.tsx`, `components/mobile/sheets.tsx`, `components/mobile/route.tsx`, plus the minimal edits in `app/providers.tsx` / `components/ScreenSwitch.tsx` needed to mount the shell.

1. **Persistent shell.** On mobile the shell must survive route changes so the old screen can animate out. Mount `<MobileShell>` once, around `children`, inside Providers when `useDevice()==="mobile"` (e.g. a `DeviceChrome` client component in providers.tsx). `ScreenSwitch` keeps rendering the mobile element as `children`. DOM: `div.device > (.screens > main.screen[data-name]…) + .edge-swipe + .floating(tray) + nav.tabbar` — no phone frame and no fake status bar in the web app (edge-to-edge, safe-area insets). Check `styles/mobile.css` + `core.css` for the class names the prototype used (`.stage/.device/.screens/.screen/.tabbar/.tab/.tab-ico/.edge-swipe/.floating`, `.device.no-tabbar`, `.has-tabbar`, `.is-fixed`).
2. **Screen stack.** Port `stack/PARENT/ROOTS/TAB_OF/onRoute/show/nav` (mobile.html ~L556–660) to React: keep an array of layers `{key, node, route}`; on pathname+search change compute dir (`push` | `pop` | `tab` | `none`) exactly like `onRoute`, keep the outgoing layer rendered for 330 ms with `nav-push-out`/`nav-pop-out` (or hidden for tab), incoming gets `nav-push-in`/`nav-pop-in`/`nav-tab-in`; reduced motion → no animation. Only the top layer is interactive.
3. **Frozen route per layer.** Each layer is wrapped in `<ScreenRouteProvider value={{pathname, params, query}}>` frozen at the time it was pushed. Mobile screens MUST read route data via `useScreenRoute()` from `components/mobile/route.tsx` (`{ name, params: Record<string,string>, query: URLSearchParams, path }`) — never `useParams/useSearchParams/usePathname` directly — so the outgoing screen doesn't flash the new route's data. Route `name`s follow the prototype: welcome, explore, map, parking, reserve, checkout, confirmation, bookings, booking, arrive, saved, compare, notifications, profile.
4. **Navigation API** `useNav()` from kit: `go(path, query?)` (router.push), `back()` (closes top sheet first; else stack pop; else PARENT fallback), `reset(baseKeys, target, dir)`, `replaceTop(path, query?)`. Tapping the active tab scrolls the screen to top (smooth). Onboarding gate: if `!state.onboarded` and route ≠ welcome → replace to `/welcome`; `/` on mobile → `/explore` (the `Home` export can simply redirect).
5. **Edge-swipe back.** Port `swipeBack()` (L662–700): pointer on `.edge-swipe` (18px), render the previous layer underneath with `is-under` and live transform/brightness, settle >33% width or flick; on success adopt the under-layer without re-animating.
6. **Screen frame component** `<Screen name tab? fixed? ptr? tray? onRefresh?>` → `main.screen` with `has-tabbar`/`is-fixed`, wires collapsing topbar (port `wireTopbar`), pull-to-refresh (`wirePull` L774–820, calls `onRefresh` or `actions.refreshAvailability()` + toast), count-up of `[data-count]` on first mount (`countUp`), and tells the shell whether to show the tab bar / compare tray. Tab bar: 5 tabs (Explore, Map, Bookings, Saved, Profile) with live-bookings badge, blur, safe area; active tab per `TAB_OF`.
7. **Kit** (`kit.tsx`): `Topbar` (props as prototype `topbar(o)`: title, sub, large, eyebrow, eyeLime, lead, overlay, back, backLabel, actions; back label = previous stack screen's TITLE), `Bell`, `Seg` (segmented control with sliding thumb, `wireSegs`), `Wheel` (scroll-snap picker columns, L745–773), `Price` (+ rolling update), `Empty`, `Skel`, helpers `vt, W, measureOne, tl, opensLabel, plain, durH, amen` (reuse `components/desktop/common.tsx` helpers where identical — import, don't duplicate), `RCard` (result card, L1020–1050 incl. save/compare/book acts and heart/compare sync), `SearchBar`, `WhenPill`, `FilterRow`, `CompareTray`.
8. **Sheets** (`sheets.tsx`): use `components/shared/Overlay` `Sheet` (it already renders a bottom sheet with grabber + drag on `body.m`; verify drag-to-dismiss matches `dragSheet` L701–722, fix in Overlay only if needed without breaking desktop). Port as React components with `open/onClose`: `TimeSheet` (L828–871, wheel pickers, day items), `DestSheet` (L872–901), `FilterSheet` (L902–937), `SortSheet` (L938–944), `VehicleSheet` (L945–973), `CalendarSheet` (L974–987). Provide `useSheet()` host similar to desktop `useModal()` so screens can `openSheet(({open, close}) => <X …/>)`.
9. Replace the `Stub`s in `components/mobile/index.tsx` with a stub that renders inside `<Screen>` + `<Topbar>` so phase 2 can drop real screens in. Create `components/mobile/_demo.tsx`-free verification: a Playwright script in `scripts/` (gitignored output) that walks explore → parking → reserve → back-swipe and screenshots at 390×844 with a mobile UA.

Done when: `npx tsc --noEmit`, `npm run lint`, `npm run build` all green; Playwright at 390×844 shows tab bar, push/pop animation classes applied, swipe back works, sheets open/close with drag, zero console errors; desktop at 1440 unchanged. Write a short API note at the top of kit.tsx. Commit locally (`git commit`, do not push).

## Phase 2 — screens (two builders in parallel, after phase 1)

Each screen = `components/mobile/<Name>.tsx`, exported through `components/mobile/index.tsx` with the existing export names. Port the prototype `Screens.<name>` render + mount + acts + onState/tick into idiomatic React (state from `useApp()`, 1-second countdowns via `useNow(1000)`, sheets via `useSheet()`, toasts via `useToast()`, confirms via `useConfirm()`), using the kit. Keep every string, number, class name and animation from the prototype. Reserve → Checkout passes `s, e, m, v, req, note` in the query exactly like desktop `Reserve.tsx`; Checkout handles `state.demo.nextPaymentFails`.

- **Builder A** (prototype L988–1500): Welcome (+ onboarding: guest / sign-in local only, no OTP), Home (redirect), Explore (search bar, when pill, filter row, results with skeleton → cards, pull-to-refresh, compare tray), MapScreen (SvgMap full-bleed, bottom card carousel, search-this-area), Facility (`parking`: illustration hero overlay topbar, heat-map availability, amenities, reviews, sticky action bar), Reserve (dial, mode seg, vehicle, requirements, live validation + price roll), Checkout (bill, promo, pay methods, processing, failure path), Confirmation (pass print animation, calendar sheet, check badge). Shared `PassView` lives in `components/mobile/pass.tsx` (from `passHTML` L1452) — Builder A owns it; Builder B imports it.
- **Builder B** (prototype L1500–1840): Bookings (groups upcoming/active/past, `bcard`), BookingDetail (`heroState`, live countdown ring, extend/cancel/exit/modify sheets L1607–1700, calendar, directions), Arrive (QR pass full screen, brightness hint, mark arrived/exited), Saved (saved places + saved searches tabs, alerts toggles), Compare (max 3 columns), Notifications (read/unread, swipe or buttons to remove, mark all read), Profile (user, vehicles, payment pref, saved places, notification/pref switches, text size, reduce motion, docs sheets, sign in/out local, hidden developer options after 5 taps on version: test clock, jump, reset). Until `pass.tsx` exists, import it anyway — Builder A creates it first.

Both: verify each screen with Playwright at 360×780 and 390×844 (mobile UA) against `next build && next start`, compare with the prototype screenshot of the same screen, zero console errors, no horizontal overflow. Commit locally per screen group (`git add components/mobile/<files>` only — never `git add -A` while the other builder is working).
