## Hard product requirements (from the client)
1. **Device-based version**: laptops/large screens get the DESKTOP version, small screens get the MOBILE version. Breakpoint 900px (`matchMedia('(min-width: 900px)')`). Switch live on resize/rotate. Initial server guess from the `sec-ch-ua-mobile` / user-agent header so the first paint is right; the client confirms by width.
2. **Mobile must look and feel like a real native app** — exactly as the prototype: push/pop screen transitions, edge-swipe back, bottom tab bar with blur + safe areas, large collapsing titles, draggable bottom sheets, wheel pickers, pull-to-refresh, press feedback not hover, no scrollbars/underlines/text selection on controls, standalone PWA (manifest + apple meta + theme-color, installable, `display: standalone`). No phone frame in the web app (that was only for previewing the HTML on a laptop) — mobile is always edge-to-edge.
3. **No login required**: every feature works without an account; no OTP, no email verification anywhere. The user is a local "Riya Sharma" profile editable on the Profile page; there is a "Sign in" row that only switches guest/named mode locally. Never block any action behind auth.

## Stack
- Next.js 15 (App Router) + TypeScript + React 19, no Tailwind (port `core.css` as `app/globals.css` with CSS variables; mobile/desktop CSS as `styles/mobile.css`, `styles/desktop.css`). `next/font/google` for Schibsted Grotesk, Onest, JetBrains Mono (CSS vars `--font-display/--font-body/--font-mono`).
- No backend: all state client-side in localStorage (`parkly.app.v1`) via a React context + `useReducer` (`lib/store.tsx`), seeded from `buildSeedState(now)`. All Date/localStorage reads happen after mount (no hydration mismatch): render a tiny splash until mounted.
- `lib/data.ts` (typed port of data.js), `lib/engine.ts` (pure functions: pricing, availability, validation, search ranking, status, refund, calendar links, formatters), `lib/actions.ts` (the A.* actions as reducer cases / thunks), `lib/device.tsx` (DeviceProvider + `useDevice()` → 'mobile'|'desktop').
- Shared components (`components/shared/`): `SvgMap`, `Dial`, `QRCode` (port the encoder), `FacilityIllustration`, `Pass`, `Bill`, `OccupancyBar`, `Plate`, `Stars`, `AmenityIcons`, `Ring`, `Icon` (lucide-react is fine), `Sheet`/`Modal` (bottom sheet on mobile, centred modal on desktop), `Toast` provider, `Confirm` dialog.
- Routes (App Router): `/` (desktop → landing; mobile → explore/welcome), `/welcome`, `/explore`, `/map`, `/parking/[id]`, `/reserve/[id]`, `/checkout/[id]`, `/confirmation/[id]`, `/bookings`, `/bookings/[id]`, `/bookings/[id]/arrive`, `/saved`, `/compare`, `/notifications`, `/profile`. Each `page.tsx` is a thin client wrapper: `<ScreenSwitch mobile={<MobileX/>} desktop={<DesktopX/>}/>`. Mobile screens live in `components/mobile/`, desktop views in `components/desktop/`. Mobile shell = `components/mobile/MobileShell.tsx` (tab bar, screen-stack transitions via a `template.tsx`/route-change effect, edge-swipe back using `router.back()`); desktop shell = `components/desktop/DesktopShell.tsx` (sidebar, `/` landing without sidebar).
- `public/manifest.webmanifest`, icons (generate the P logo as SVG + 192/512 PNG), `app/layout.tsx` with metadata (title "PARKLY — Parking, reserved", theme-color, apple-mobile-web-app-capable, viewport-fit cover).
- Lint clean (`next lint`), typecheck clean, `next build` green. `.gitignore` for node_modules/.next. `README.md` (what it is, how to run, device switch, no-login note, deploy on Vercel).
